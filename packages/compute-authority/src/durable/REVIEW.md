# Local domain review and RTD receipt

Scope: only new files in `packages/compute-authority/src/durable/`. Approved reference modules were not edited by this lane. No commits, push, merge, cloud calls, installation, credentials, host configuration, training or database-lane operations.

Six local review passes (no delegated/background agents):

1. Storage/structure: SQL rows own workers/devices, immutable intake, placements, attempts, leases, reservations, sealed staging pointers, verification receipts, scoped commands, renewal/requeue identities, ordered audit/outbox and stop receipts. No whole-state blob, Map authority, raw transaction statements or asynchronous callback in the domain port. Schema initialization is host transactionSync too. Node test adapter uses its own BEGIN/COMMIT only outside production code.
2. Atomicity/compilation: unexpected SQL/outbox fault propagates and rolls back all coupled rows; controlled rejection gates precede mutations. Review found a device-change rejection after CPU update; moved validation ahead of updates and added regression. `tsc --noEmit` covers the repository. Node cursor rows are copied into plain records before canonical serialization.
3. Trust/security: trusted context DI is deliberately not authentication. Mandatory context epoch checks precede command replay/effects; options bind namespace and issuer on reopen. Executor identity must own enrolled worker. Owner-only enrollment/quota/cancel/requeue/reconciliation/recovery; verifier-only actual-byte finalization; projector/owner outbox. Plain bearer never persisted; HMAC descriptor replay and keyed issuer binding survive normal restart. Existing public endpoint fail-closed wrapper belongs to parent.
4. Protocol/content: general CPU/RAM >0; edge resources exactly zero/no devices and claims reject. Reservations count held + quarantined, select a single qualifying individual GPU, with partial unique exclusivity and capacity/attempt/receipt triggers as backstops. Intake content hash/policy never changes. Expiry on command/read sweep, capped sequence-idempotent renewals, independent VERIFYING deadline, expected generation/request ID requeue, pure + reconstructible retries only, terminal winner/receipt immutability, owner process-stop reconciliation before physical release. Finalization conservatively fences every peer lease on that worker.
5. Journey/replay/projection: focused tests run actual Node SQLite SQL for submit→claim→stage→independent bytes→receipt→restart/replay; loss-response replay reconstructs original capability. Tests also cover rollback, stale fences, quarantine, bad independent bytes, reader re-entry cancellation, outbox prefix acknowledgement, large historical batches and schema corruption backstops. Events retain trusted actor/role, version, reason, workload/worker/quota/lease/resource/placement/artifact/receipt facts. Global event sequence provides increasing entity_version. Outbox batches are byte-budgeted; only delivered contiguous prefixes can be acknowledged.
6. Contrarian/deployment: added request epoch to command digest so keys reused after recovery conflict, rather than replaying old-epoch results. Added attempt/workload/placement/epoch SQL backstops, deletion guards for sealed artifacts/receipts/audit/placements, and historical quota/resources to events. No production-readiness or exactly-once physical execution claim. No deployment performed.

Known deferred boundaries:

- Parent owns real Cloudflare workerd/Miniflare transaction/restart/concurrent duplicate/response-loss acceptance proof and Worker wrapper. Node SQLite adapter evidence is not platform proof.
- Context, immutable byte store, process-stop attestations, workload purity/reconstructibility classification and issuer key provisioning remain trusted host dependencies. Core does not authenticate transport, sandbox executors, stop processes, implement D1 projection or run a remote pilot.
- General class is the only execution policy. Quota is active-workload admission, not CPU billing/fairness. Placement chooses an explicitly requested feasible candidate with bounded complete facts, not globally optimal placement. Device identity/geometry is immutable once registered; change requires a new worker identity. Candidate inventory bounded at 128 workers and 64 devices per worker; oversized candidate evidence fails closed.
- One projection cursor is supported. Historical command/event/attempt rows have no retention implementation; storage growth requires admission/retention policy before production. Snapshot reads full local entity tables. Key rotation/schema upgrades beyond version 1 intentionally fail closed and require an explicit migration design.
- Replayed success describes the original logical operation; a replayed old claim capability does not revive revoked SQL state. Recovery epoch is stricter: old contexts fail before replay and new contexts must use new keys.

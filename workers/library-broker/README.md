# Bounded Library broker host — local Node implementation

`brokerHandler(host)` exposes authenticated HTTPS POST `/v1/broker/read` and owner-only `/v1/broker/revocations` around `packages/storage-broker`. It is disabled unless explicitly enabled by the trusted host. It is a local Node handler, not a deployed Cloudflare Durable Object or GCP service.

The host supplies environment/authority identity, a configured owner principal, digest-to-principal authentication, private broker handles, authoritative grant lookup and fresh authorization observations. Requests cannot provide their actor, grant policy, provider URL or credentials. Readers send only grantId/requestId; the handler checks ownership before privileged refresh and reauthenticates after every asynchronous boundary, including before returning provider bytes. Owner/read body admission is separate. Four outstanding refresh slots remain charged until the underlying promises settle, even when callers time out; revocation remains available independently.

A revocation carries the relay's exact target and evidence identity. It must match this broker's environment/authority, project, immutable grant, authorization generation, policy/hash, compute fence and object identity. The handler uses `grantRevocationBinding(grant)` and returns a bound receipt only after the durable tombstone/reply transaction. Claim revisions do not grant authority. The authenticated owner credential is a host secret reference; no real credential is included here.

## Ordering and storage contract

The HTTP adapter requires the authoritative grant record to be available **before** its delivery target is registered. Private grant issuance, current authorization checks and registration are host responsibilities; there is no public grant-issue endpoint. The core can persist preemptive unknown-ID tombstones, but this lookup-based HTTP adapter does not offer that behavior. Unknown target lookup remains unacknowledged/retryable; it is never reported revoked. Delivery-before-issuance is unsupported by this adapter and must not be used as a rollout ordering plan.

The broker is stateful: grants, consumed budgets, sealed bytes, unresolved reservations and tombstones live in one Node SQLite database. Current tests reopen the file and preserve denial. Neither ephemeral cloud instance disks nor independent replica databases satisfy this contract. A future stateless GCP provider adapter needs an explicitly selected durable grant authority and consistency model. Provider credentials/session capabilities stay server-side; actual GCS generation reads/allocation/transport bounds remain trusted adapter proof gates.

Default lifetime limits are 32 grants,128 retained reads,8MiB reserved bytes and1MiB/read. Unresolved operations retain their budget and capacity. Host activation needs occupancy alerts, a reviewed reconciliation/rollover and full broker/relay/compute recovery plan. Do not prune replay or tombstone history to regain capacity.

Local HTTP tests use real in-memory SQLite and fake ports; the integration harness combines the Node handler with actual compute/catalog workerd services. No installation, provider call, deployment, spend or secret change is performed. Parent current receipts: integration/evidence/library-resilience/.

## 2026-10-18 online build host (local source candidate)

`createBuildBrokerHost` is a concrete scope-bound durable host composition in `src/build-host.ts`; `createGcsBuildBrokerHost` connects it to the existing pinned GCS reader/create-only writer. Supplied DB handles, managed credential resolvers, authority origin/environment/id, exact per-attempt compute scope and immutable owner namespace approval are mandatory. No listen/start, namespace discovery, provisioning, ambient SDK credentials or provider operation occurs at import. Constructor invocation initializes the supplied databases; none was invoked during implementation.

`createOnlineStorageBroker` persists a distinct mode+namespace binding. It does not reopen a synchronous namespace as an online one. Local policy/grant/tombstone checks are synchronous; actual compute authorization uses authenticated fixed-origin nonce-bound `/v1/builds/access` reads before and after provider I/O and before each cached reply. Access maintenance commits the authority clock/expiry before a permanent denial observation. Recoverable heartbeat denial does not permanently revoke a grant. A successful final online observation is the distributed read authorization point; later revocation cannot retract delivered bytes.

Explicit signals reach online issuance/read, remote checks and provider work. Cancellation blocks subsequent work and returns no successful bytes/issuance; it is not proof of provider termination. Online duplicate in-flight reads are refused as busy, preserving individual cancellation ownership; completed exact requests can replay after new authorization. Legacy shared-flight behavior remains separate. Uncooperative operations retain admission until settlement, and unknown reservations remain durable.

Capacity requests need an exact stable operation key; lost replies replay the same receipt and debit. Writer and issuer receive that explicit receipt, not a mutable current-reservation slot. Scope/policy/principal/compute/object/generation and size are enforced. Grants expose actual `admin.issue` receipts only after durable intents and actual remote authorization. Unknown provider writes/reads retain evidence and do not trigger namespace rollover.

Revocation commits a local deny marker before cross-DB delivery, separately journals every command by exact key/payload and returns the broker's actual receipt unchanged. `reconcileOnce(signal)` explicitly retries retained delivery and checks at most 32 issued/pending grant intents. Network or recoverable freshness failures stay pending; they do not become revocation evidence. There is no autonomous polling loop or scheduler. Existing authenticated revocation delivery also enters this durable path.

`createBuildNamespaceSet` accepts only a finite preapproved set of at most 512 supplied namespace configurations/DB pairs. It first searches exact prior operation receipts across the complete set, rejects conflicting prior debits, then chooses eligible approved capacity. The final reservation transaction remains authoritative. Each namespace keeps the old 32-grant/8MiB lifetime bounds, tombstones and unknown operations; no reset/rollover is automatic. Publication registers only actual generation-pinned write receipts; reads require an exact approved or verified-published reference. Credentials remain host-only.

This composition has not been compiled, executed, provisioned, installed or validated. Existing databases have no implicit migration path; schema/binding mismatch holds evidence and fails. Private roots, actual tree seals, account/provider permissions, credentials, disk headroom and all operational approvals are still prerequisites.

## New durable operator view

POST `/v1/operator` inside the existing ComputeAuthority transport. Exact envelope `{expectedEpoch,request:{afterEvent,limit}}`; afterEvent safe nonnegative integer, limit1..64. Owner only, same header auth/re-auth after body, epoch fence. It is read-only and MUST NOT call snapshot(), sweep(), core.execute(), consume/ack the outbox or mutate liveness/leases. Read current SQL transactionally. Do not expose generic SQL or accept target namespace from input.

Reply version1 includes source `{environment,authorityId,epoch,observedAt,head}`; bounded `workers`, `workloads`, `leases`, `attempts`, `placements`, `receipts` arrays; `events` as a cursor page `{after,through,head,hasMore,items}`; explicit family `windows` with total/returned/truncated. DTO types exported from new workers/compute/src/operator-feed.ts are the bridge/UI source of truth. No raw capability, capability hash, bearer/digest, issuer material, journal, full workload specification, artifact bytes, raw event payload or arbitrary provider error enters this DTO.

Use explicit SQL column selection. Workers show approved capacity/class/incarnation/quarantine, current enrollment revision/expiry/revocation/lastSeen/sequence/freshness if any; no false connection boolean. Read actual enrollment table/meta shapes. Missing enrollment is null/unknown. Bound worker rows32, workload rows32 (active prioritized), lease/attempt rows64, receipt rows32, placement rows8. Placement projection must retain selected-worker/reason/policy/resources and bounded candidate rejection facts with explicit omitted-candidate count; do not claim optimal scheduling or invent reasons for jobs never placed. Preserve placement snapshot created by core, but whitelist safe fields. Cap each candidate family and textual facts. Order windows deterministically; do not label arbitrary lexicographic order latest. Return total/count/truncation so omitted history is visible. Event page reads immutable event metadata only, ascendingseq, actual after/through/head; never acknowledges or clears independent consumers. Max serialized view256KiB; if bounded projections still exceed, fail closed with fixed operator-view-capacity rather than silently truncate JSON. No mutation or broad database snapshot fallback on failure.

## Operator host and browser contract (parent implementation)

The host serves fixed local static assets and an allowlisted same-origin bridge; no direct browser authority credentials. Strict loopback bind/Host checks and same-origin JSON mutation policy; no CORS workaround. Production remote exposure requires its own access-control decision.

- GET `/api/operator/view?afterEvent=<n>`: host uses fixed configured HTTPS authority origin and owner credential reference, discovers/validates authority environment/ID/epoch then POSTs the new durable view. Returns the safe DTO in a source wrapper marking local/remote authority and request/observation times. No fixture fallback. Unconfigured/unavailable/stale/partial/error remain visible, never fake empty-success/live labels.
- POST `/api/pilot/jobs` with exact `{requestId,workloadId}`: only a host-configured immutable pilot input/specification may be prepared; no browser-selected URL, principal, template, shell, file path, quota, profile, verifier or generic command. Persist stable full submit intent before network; retry exact same payload/key after response loss. Operational action flag off by default. Quota/enrollment/profile are separate owner CLI/approval paths, not implicit submission side effects.
- GET `/api/pilot/jobs/<id>/result`: only for a known scoped workload with matching independent accepted receipt; fetch exact sealed artifact through owner endpoint, recheck hash/size/receipt binding, return safe bounded text/metadata. Staged bytes alone are not accepted output.
- Static browser assets `operator/index.html`, `operator/operator.css`, `operator/operator.js`: workers, queue, attempts, placement/rejection reasons, accepted output and audit. Safe DOM text, explicit source/age/window limits. No browser tokens or localStorage secrets. No fictitious live fixture display.

Host/client/verifier starters must import existing modules through the existing approved TS loader strategy; no build/install is performed now. Private persistent state and managed credential reference resolution must be concrete. Worker launcher composes boundedStep+NodeHostJournal+actual NodeCliAdapter/NodeStagingPort/WorkerRuntime; stable supervisor step IDs and bounded retries, no lock theft/crash rerun. Edge injects a runtime that fails if execution is reached; it never provisions Docker. Verifier is separate role/driver with persisted stable request identity and actual existing /v1/verify. Do not auto-clear post-success quarantine or manufacture physical stop receipts.

No vetted image digest, socket path, live authority URL or credential is invented. Missing activation inputs are explicit errors/gates, not fake successful adapters. ### Accepted result point lookup

Add owner-only HTTPS POST `/v1/operator/result` exact `{expectedEpoch,workloadId}`. Read current SUCCEEDED workload/winner, immutable receipt and matching sealed artifact in one read transaction; verify full receipt/seal/actual byte/hash/length binding and epoch. No caller-supplied artifact reference. Pilot result bytes must fit4096; oversized/unavailable/nonaccepted/mismatched records fail explicitly rather than becoming a successful empty result. Return `{version:1,ok:true,environment,authorityId,observedAt,receipt:{workloadId,leaseId,sha256,bytes,epoch,generation,incarnation,verifier,verifiedAt},bytesBase64}`. The host bridge rechecks strict base64/hash/size and configured workload scope before returning bounded plaintext/metadata to UI. The browser never receives raw seal references or capabilities. Content SHA256 is safe result metadata; the projection's forbidden digests are credentials/capabilities/issuer checks.

### Browser response envelopes

GET `/api/operator/view?afterEvent=n` returns HTTP200 `{version:1,state:'connected',sourceMode:'local-authority'|'remote-authority',requestedAt,receivedAt,view:OperatorView,actions:{submitEnabled:boolean,inputConfigured:boolean,template:'epoch-event-summary-v1'}}`. It means successful authenticated authority observation, not proven worker connection/execution. Missing config or upstream error returns non200 `{version:1,state:'unconfigured'|'unavailable',code:string}`. Browser retains old data only with explicit stale/error labeling. The initial unconfigured server may serve assets and error responses only, with no defaults enabling network/credentials/actions.

POST `/api/pilot/jobs` exact `{requestId,workloadId}` returns HTTP200 `{version:1,state:'submitted',workloadId,requestId,replayed:boolean}` only after actual durable authority `{ok:true,workload}` response matches intended bound workload; response loss returns explicit unavailable/uncertain and retains original journal intent/key. No simulated success. GET `/api/pilot/jobs/<id>/result` returns `{version:1,state:'accepted',receipt:<safe point-lookup receipt>,text:string}` only after host actual-byte verification. Nonaccepted/staged/missing/foreign results are errors, not empty successful text.

UI fixed same-origin API, no user-entered server URL/token/config. Default refresh15seconds, one active request at a time, bounded response/body and deadline; abort does not imply provider stopped. Bounded audit window with explicit after/through/head/hasMore, user paging/follow-latest; browser is not durable audit storage. All hidden/omitted worker/job/placement/event history disclosed using window metadata. Submit disabled until actions/inputConfigured true and source connected; preserve same IDs when retrying an uncertain action. Output must say independently accepted only after real receipt-bound lookup. No generic destructive/reconcile/enroll/verify buttons.

### Local operator session access control

Loopback binding is not operator authentication. The actual operator server therefore requires a separate host-managed `operatorCredentialReference` in its private config, distinct from authority references and credential values. It exposes GET `/api/operator/session` (unconfigured/locked/ready), same-origin JSON POST to that path `{credential}` for a transient local operator login, and POST `/api/operator/logout` `{}`. Successful login sets a short-lived HttpOnly SameSite=Strict cookie; configured authority owner/submitter/verifier tokens are never browser inputs. No localStorage credentials or token URL parameters. This adds no actual secret/provisioning now; an approved local operator reference is an activation prerequisite. The server is loopback HTTP only, not remotely exposed; remote access requires a separate TLS/access-control plan. Protected API401 is `state:'locked'`; no credentials/default sessions are created in unconfigured mode.

The connected actions object additionally carries `allowedWorkloadIds` (1..8 configured IDs). The backend enforces this exact set, independently of UI. No quota/enrollment/verification role is granted to the browser. Client state still cannot prove a process ran or stopped.

## Repair-wave producer/consumer amendments

OperatorConfig now requires distinct submitterPrincipal/verifierPrincipal and explicit inputAuthorityId. The latter pins the event-source namespace; authorityId independently pins the actual compute control plane. Supplied input namespace pilot-input is synthetic. Mutation journal binding includes actual owner/submitter credential fingerprints privately; captured tokens are checked before replay and dispatch. No fingerprints are browser fields.

Validated input provenance is {kind:'synthetic-pilot-input',actualChainObservation:false,inputSha256,inputAuthorityId,template:'epoch-event-summary-v1'}. actions.provenance is this object only when inputConfigured true, otherwise null. Submission and accepted-result bridge replies include provenance. UI labels both submission and accepted computation as synthetic input, never actual chain observation.

Authority /v1/operator/workload is an owner-only epoch-fenced exact-ID lookup with {expectedEpoch,workloadId}; response {version:1,ok:true,environment,authorityId,observedAt,workload,lease,receipt}, nullable objects in the same public projection types as OperatorView. Verifier uses this bounded point lookup and resolves pending exact verification intent before discovery. /v1/operator/result additionally projects safe intended-workload fields {id,principal,specification,expectedHash,maxBytes,cpu,ramMib}; host compares those and receipt against frozen input plan and distinct configured verifier before exposing accepted text. No secret/capability/seal token/raw event payload is exposed to browser.

Local sessions have bounded server membership (32) and 15-minute expiry. Logout removes current nonce; process restart invalidates all. Route remains loopback-only. These are source contracts, not executed guarantees.

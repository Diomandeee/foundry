# Independent recovery checkpoint and reconciler

Local implementation only. No provider identity, service deployment, timer, approval route or production callback is activated.

`checkpointStore(port, scope, now)` owns a separate transactional SQLite ledger. Keep this database outside catalog archives and restore destinations. Scope fixes environment, checkpoint/catalog/compute/relay authorities, project, policy version/hash and approving owner. The private admin handle accepts an authenticated owner context and an explicit expected-revision command with archive hash (or null to withdraw), stable key and reason. Approval is a product/owner decision, not a consequence of export/upload. The private reader returns the latest decision; a separate host-only recovery handle can issue bounded recovery permits; no decision or withdrawal fails closed. Decisions and scope are append-only, bounded to 1,024 lifetime decisions; the final slot is reserved for withdrawal (ordinary approvals stop at 1,023 retained decisions). Identical command replay returns its historical result; reconciliation always reads current latest. SQL guards reject replacement/deletion/update and out-of-order inserts. Reopening checks exact schema and binding.

`recoveryReconciler(scope, ports)` returns the host `reconcileRecovery(challenge, signal)` callback. It never accepts an archive checkpoint from a client. It reads the separate ledger, requires its latest approval to match the restored service archive, validates restore-specific target hashes and all exact policy/compute bindings, registers generation-specific catalog targets in the persistent relay, catches the independent feed up, then observes every compute fence. If observations advance beyond the cursor it catches up and observes again. Retained applicable revocation evidence invalidates an attempt even if delivery was already acknowledged. Invalid attempts are returned as invalid; the catalog atomically cancels them before clearing quarantine. Accepted verified attempts remain valid despite worker quarantine. Missing source, failed registration, changed approval, stale/foreign observations, head/epoch rollback or incomplete catch-up never produces a proof.

`reconcilerHttp(config, ports)` supplies authenticated compute observations/feed reads over a fixed HTTPS origin with a host-managed credential reference. It uses owner-only existing endpoints. Disabled by default. No caller-supplied URL or credential reference, redirects, non-200 or oversized JSON. Credentials remain in trusted host memory. Response errors do not include provider bodies. The transport returns untrusted page JSON as unknown until domain validation. The reconciler itself is a host-private callback, not an unauthenticated HTTP proof server.

Limits: 32 restored live intents per pass, 16 pages (64 events each), 8 catch-up/observation rounds, 4 seconds overall, 1-second source freshness, four concurrent observation lanes, one unresolved reconciliation at a time. HTTP allows four actual outstanding operations, including abort-ignoring work; 1-second deadline per POST, 64 KiB/response. Timed-out work retains admission until it settles, and checks cancellation before any late persistence. Capacity exhaustion leaves quarantine closed and requires reviewed retention/migration; no implicit reset. Limits are admission boundaries, not production throughput evidence.

After all observations, the separate checkpoint ledger atomically verifies its current approval revision and records an append-only recovery permit bound to restore ID, exact archive, challenge hash, revision, issuing authority and times. Its deadline is at most one second and no later than any qualifying active compute lease's expiry. There are 1,024 lifetime permit slots, independent of approval/withdrawal capacity. An already issued permit is an explicit **irrevocable bounded approval lease**: withdrawal or supersession stops new permits immediately, while a permit issued earlier may be consumed until its recorded deadline. There is no promise of cross-service instantaneous revocation. The catalog rejects the proof at/after that deadline and verifies exact challenge binding; late delivery cannot revive an expired active compute lease. Accepted SUCCEEDED results retain their distinct historical semantics. Permit bytes are trusted host output, not a public signed credential or client-supplied capability.

The catalog still owns `finishRecovery`, owner reauthentication and unchanged-state comparison. The production LibraryAuthority callback remains absent. A Node host must durably place checkpoint/relay databases separately from catalog recovery and explicitly inject the callback over a reviewed authenticated bridge. No bridge or credential installation is included. Test-only Miniflare service bindings prove this call path locally.

This is point-in-time reconciliation, not a distributed transaction. Normal publication still needs current authorization and byte verification, revocation delivery continues after recovery, and upstream changes after observation remain possible. This ledger cannot detect coherent rollback of itself plus all authorities; independent storage/backup/approval governance is an activation requirement. It also does not recover GCS bytes, broker grants, relay state or compute state from a catalog backup.

Fully validated source knowledge persists separately from fallible event/page retention. A retention failure can leave the source watermark ahead of the cursor; that is a durable closed barrier, never permission to forget the higher head. Exact historical page replay stays read-only. Changed local relay/checkpoint schemas are not migrated automatically.

## Host composition and local checks

The three entry points are `src/index.ts` (`checkpointStore` and scope/issuer types), `src/reconcile.ts` (`recoveryReconciler`) and `src/http.ts` (`reconcilerHttp`). From source-root host code, imports use `./packages/library-checkpoint/src/index`, `./packages/library-checkpoint/src/reconcile` and `./packages/library-checkpoint/src/http`; package-name installation has not been verified.

Construct the independent store with `checkpointStore(checkpointTransactionPort, scope, now)`. Retain `store.admin` only in the owner approval path; pass `store.recovery` to the reconciler's `checkpoint` port. Construct the authenticated source with `reconcilerHttp(httpConfig, {credential, fetch})`, where credential resolves only the configured managed reference. Then construct `recoveryReconciler(scope, {checkpoint: store.recovery, relay, owner, dispatcher, source, now})` and inject the returned function as the catalog host's `reconcileRecovery`. All named ports are trusted host dependencies described by the exported interfaces; this recipe does not install or authenticate the cross-runtime bridge. Do not expose `store.admin` or proof submission as an unreviewed client endpoint.

Permit consumption linearizes at the trusted authority clock sample on entry to `finishRecovery`, before its synchronous atomic application. It rejects admission at/after expiry (including active compute expiry); it does not promise transaction completion before expiry. There is no await between this admission and the readiness transaction. Bridge integrity and clock agreement remain activation requirements.
